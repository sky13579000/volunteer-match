# 보안 설계 요약

> 설계와 구현 사실을 적은 문서입니다. **외부 보안 인증·모의해킹을 받은 것은 아니며**, 운영 전 고객 보안 점검이 필요합니다.

## 원칙
1. **권한 필터가 먼저**: 검색·AI 후보를 순위 매기기 *전에* 읽기 권한으로 거릅니다. 목록·검색·AI·캘린더·리포트·활동 피드·알림이 모두 같은 권한 함수(`derive_acl`)를 씁니다.
2. **존재 자체를 숨김**: 읽을 수 없는 문서는 403이 아니라 404. 권한 신청은 문서 존재 여부와 무관하게 같은 응답.
3. **관리자는 관리하되 읽지 않음**: 관리자는 권한·삭제를 관리하지만 문서 본문 열람 권한은 별개. 리포트·기록물 화면도 열람 불가 문서의 제목은 숨김.
4. **업무 DB는 단일 문**: 화이트리스트 테이블·컬럼, 컬럼 마스킹(역할/등급), 행 정책, 파라미터 바인딩, 읽기 전용 계정. 사용자·LLM이 만든 SQL은 DB에 닿지 않음.
5. **LLM을 믿지 않음**: 근거 외 내용 차단(인용 번호·숫자 일치 검증), 프롬프트 주입 문구 제거, 실패 시 근거 발췌로 대체.

## 통제 항목
| 영역 | 구현 |
|---|---|
| 인증 | 서명 토큰(HMAC), SSO 프록시 헤더(신뢰 프록시 주소 제한), 데모 헤더(운영 비권장), API 키(SHA-256 저장·만료·폐기·범위·관리 API 차단) |
| 감사 | 모든 질문·문서 행위를 해시 체인 감사 로그에 기록, 변조 검증(`verify-audit`), CSV |
| 무결성 | 파일 SHA-256, 다운로드 시 검증, 백업 매니페스트 검증 |
| 외부 공유 | 토큰 해시 저장, 만료·횟수·비밀번호(시도 제한), 공유 시점 버전 고정, 다운로드 제한 속성 |
| 웹 보안 | 엄격 CSP(스크립트 self만, 인라인 스타일 금지), textContent 렌더링(XSS 방지), 보안 헤더, 요청 크기·속도 제한 |
| 연동 | HMAC 서명 + 5분 유효 + 재전송 거부, 약한 비밀값은 비활성, 송신 웹훅 재시도·제목 비포함 기본 |
| 개인정보 | 규칙 기반 검출(값 미저장), 경고/차단/보안등급 상향, 답변 내 개인정보 가림(역할 예외 가능) |
| 기록물 | 법적 보류·보존기간은 관리자에게도 적용, 폐기는 별도 승인자, 폐기 대장 |
| 운영 | 비-root 컨테이너, 읽기 전용 DB 계정, 설정 비밀값은 환경변수, 시스템 상태 화면 |

## 알려진 한계 / 운영 전 필수 조치
- 데모 로그인(헤더)은 **운영 금지**. 토큰 또는 SSO 프록시 + HTTPS 사용.
- 개인정보 검출은 규칙 기반이라 오탐·미탐이 있음(이름·주소 등 비정형 개인정보는 검출하지 않음).
- 저장 파일은 **암호화하지 않음**(디스크/볼륨 암호화로 보완 권장). 감사 로그 해시 체인은 변조 *탐지*이며 외부 보관(WORM, SIEM)과 병행 권장.
- 속도 제한은 단일 프로세스 메모리 기준. 다중 인스턴스에서는 프록시 단 제한 필요.
- SQLite 단일 파일 기준 시험. 대규모·고가용성은 PostgreSQL + 백업 정책 필요(미시험).
- 외부 침투 시험, 코드 서명, SBOM, 취약점 대응 프로세스는 **미수행**.

## 도입 시 점검표
- [ ] 인증 모드를 `token` 또는 `proxy` 로 설정, `trusted_proxies` 지정, 서비스 포트는 프록시만 접근
- [ ] HTTPS(사내 인증서), 방화벽, 서버 계정 권한 최소화
- [ ] 업무 DB는 SELECT 전용 계정, `config.json` 화이트리스트 검토
- [ ] `golden.json` 을 실제 문서/계정으로 작성해 `eval` 의 `leaks: 0` 확인
- [ ] 백업·복원 훈련(`backup`, `verify-backup`, `restore`), 감사 로그 외부 보관
- [ ] 개인정보 정책 모드 결정(warn/block/raise_level), 기록물 분류표·보존기간 확정
- [ ] 관리자 계정 분리(신청자≠승인자 가능), API 키는 연동 전용 계정으로 최소 권한 발급
