# ICC JEJU 문서·AI 플랫폼 — 솔루션 소개

> 제주국제컨벤션센터(ICC 제주)처럼 **계약·규정·회의록·정산 문서가 흩어져 있고, 권한과 보존·감사 요구가 높은 조직**을 위한 문서 중앙화(EDM) + AI 지식 검색 플랫폼입니다.
> 이 문서는 도입 검토용 요약이며, 확인된 것과 아직 확인되지 않은 것을 구분해 적었습니다.

## 1. 해결하는 문제
| 현재 | 도입 후 |
|---|---|
| 계약서·회의록·메일이 부서별 폴더, 메신저, 개인 PC에 흩어짐 | 한곳에 등록, 폴더·분류·권한으로 통제 |
| "어느 게 최신본인가" 반복 확인 | 버전·체크아웃·결재 승인본만 "현행" |
| AI 도입 시 권한 없는 문서까지 답변에 노출될 위험 | **볼 수 없는 문서는 검색·AI 모두 대상에서 제외**, 답변마다 출처 |
| 보존기간·폐기·감사 대응이 수작업 | 분류표 기반 보존기간, 폐기 심의·폐기 대장, 변조 방지 감사 로그 |
| 문서와 업무 DB(계약금액·납기) 불일치를 사람이 대조 | 문서에서 금액·납기를 추출해 DB와 **호출자 권한으로** 자동 대조 |

## 2. 핵심 기능 (v0.6, 구현·자동 시험 완료)
**문서 관리** 폴더 트리·권한 상속(열람/편집/관리/제외) · 문서번호 자동 채번 · 버전·체크아웃·버전 비교/복원·SHA-256 무결성 · 결재(순차/병렬/위임/반려) · 만료·법적 보류·휴지통 · 댓글/@멘션/구독/알림(앱·메일) · 즐겨찾기·최근·저장 검색 · 관련 문서 · 외부 공유 링크(기간·횟수·비밀번호) · ZIP 일괄 등록/내보내기 · 양식 + 온라인 Markdown 편집 · 일정 캘린더 · 권한 신청/승인 · 기밀 문서 워터마크

**AI** 하이브리드 검색(BM25 + 퍼지/임베딩) · 근거 인용 답변 · 근거 없으면 답변 거부 · LLM 연결 시 인용·숫자 검증 · 문서 한 건 질의 · 정확도/권한 누출 자동 평가(골든셋)

**기록물·보안** 기록물 분류표(보존기간 연계, 영구 보존) · 폐기 심의(신청자≠승인자)·폐기 대장 · 개인정보 검출(주민·외국인등록번호, 카드, 여권, 전화, 이메일 — 경고/차단/보안등급 상향) · 감사 로그 해시 체인 · API 키(범위 제한, 관리 기능 차단) · 서명 웹훅(수신/송신)

**운영** 관리자 리포트(추이·결재 소요·AI 사용·보존·공유·저장) · 사용자/조직·시스템 상태 · 조직도 CSV/LDIF 동기화 · SSO 프록시 모드 · 백업/복원(무결성 검증) · Windows/Linux/Docker 실행

## 3. 구조
```
브라우저(SPA) ──HTTPS──▶ [SSO 프록시] ──▶ 플랫폼 서버(Python, 외부 패키지 없음)
                                           ├ 문서 저장소(파일 + SQLite/PostgreSQL 메타)
                                           ├ 검색 색인 + 권한 필터(먼저 거르고 나중에 순위)
                                           ├ 업무 DB 게이트웨이(읽기 전용, 컬럼·행 정책)
                                           └ (선택) 사내 LLM / 임베딩 서버 (OpenAI 호환)
그룹웨어 ◀─서명 웹훅─▶ 플랫폼 ◀─API 키─ 업무 시스템
```
폐쇄망 설치 가능(외부 호출 없음). LLM 없이도 "근거 발췌" 답변으로 동작합니다.

## 4. 검증 현황 (이 저장소 기준)
- 자동 시험 **459건**(단위·통합) + 브라우저 e2e **86건** 통과, 권한 누출 평가 0건. PostgreSQL·Oracle 연동 시험은 해당 DB가 있을 때만 실행(과거 검증, 최신 기능 후 재실행은 환경 필요).
- 성능(5,000건 기준): 검색 약 0.1초, 단건 등록 약 0.13초(개발 PC, 단일 프로세스).

## 5. 솔직한 한계 (도입 전 확인)
| 항목 | 상태 |
|---|---|
| PDF·한글(HWP)·오피스 **본문 추출/OCR** | 텍스트·마크다운·이메일·일부 오피스(docx/xlsx)·선택 설치 pypdf. **HWP·스캔 PDF OCR은 미구현** → 실제 문서로 시험 필요 |
| 브라우저 내 PDF/오피스 **미리보기** | 이미지·텍스트만. 나머지는 다운로드 |
| 동시 사용자 | 단일 프로세스·SQLite 기준 수십 명 규모 시험. 대규모는 PostgreSQL + 다중 인스턴스 설계 필요(미시험) |
| SSO | OIDC/SAML 직접 처리 아님 → 인증 프록시 방식(예시 compose는 **실행 시험 전**) |
| 특정 그룹웨어 커넥터(더존 등) | 공개 사양 미확인 → 범용 수신(`field_map`)·중계 방식 제공, 실제 연동은 제품 확인 후 |
| 모바일 앱·전자서명·도장 | 없음(모바일 웹 반응형만) |
| 외부 보안 인증(CC, ISMS-P 등) | **취득하지 않음**. 보안 설계는 `docs/SECURITY.md`, 외부 점검은 별도 필요 |
| 센터 규정 | 데모 규정은 **예시 초안**(실제 원문 아님) |

## 6. 도입 절차 (제안)
1. **현황 분석**(1~2주): 문서 유형·폴더·권한·보존 규정·기존 시스템 목록
2. **설계**: 폴더/분류표, 권한 모델(부서·역할·등급), 결재선, 양식, 그룹웨어/SSO 연동 방식
3. **구축·이관**: 서버 설치, 조직도 동기화, 문서 일괄 등록(ZIP/폴더 수집), 업무 DB 연결
4. **시험·교육**: 권한 누출 평가셋을 실제 문서로 작성해 통과 확인, 사용자 교육
5. **안정화·운영 이관**: 백업/복원 훈련, 모니터링, 정기 점검(`docs/OPERATIONS.md`)

## 7. 실행
Windows: `start-server.bat` 더블클릭 · 단일 파일: `python edm-ai.pyz demo` · 자세한 방법은 `docs/PORTABLE.md`, 시연은 `docs/DEMO_SCRIPT.md`.

## 차별화 기능 (v0.7)

- **AI 신뢰성 센터**: 골든 세트로 "권한 없는 정보가 답변에 섞이지 않는지"를 매일 자동 시험하고(노출 0건이 합격 기준), 노출이 감지되면 관리자에게 알립니다. 답하지 못한 질문을 모아 지식 공백도 보여 줍니다.
- **자연어 검색**: "내가 올린 승인된 계약서 최근 30일"처럼 쓰면 이해한 조건을 칩으로 보여 주고 필터로 바꿔 검색합니다(규칙 기반, LLM 불필요).
- **표준 조항 점검 · 버전 변경 요약**: 계약서에서 지체상금·해지·비밀유지 등 누락 조항을 키워드로 점검하고, 두 버전 사이의 금액·날짜·항목 변화를 요약합니다. 법적 판단은 하지 않습니다.
- **근거 기반 초안**: 열람 권한이 있는 문서의 발췌만 출처와 함께 모아 초안을 만듭니다(생성형 문장 없음).
