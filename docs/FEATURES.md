# 기능 목록 — 구현·검증 현황

✅ = 구현 + 자동 테스트로 검증. 테스트 수는 `python3 -m unittest discover -s tests` (단위·통합 163개) + 브라우저 e2e 58개(`tests/e2e/ui.e2e.js`).

## 1. 문서 등록 · 정리
| 기능 | 상태 | 비고 |
|---|---|---|
| 단건 등록 (파일 + 제목·유형·태그·설명·보안등급·만료일·사용자 정의 속성) | ✅ | 형식: md·txt·csv·eml·html·docx·xlsx·pptx·odf·pdf(텍스트층) 는 본문 추출, 그 외(이미지·압축 제외 등)는 본문 없이 보관 |
| 문서유형별 **자동 채번** (`CT-2026-0001`) | ✅ | 관리자가 패턴·보존 연수·결재 필요 여부·기본 결재자를 유형별로 설정, 연도별 일련번호는 중복 없이(동시 등록 16건 검증) |
| 폴더 트리 (생성·이름 변경·이동·삭제, 하위로 권한 상속) | ✅ | 내가 볼 문서가 하나도 없는 폴더는 트리에서 숨김 |

| 중복 파일 감지 (SHA-256) | ✅ | 내가 읽을 수 있는 중복만 알려 줌 (숨은 문서는 드러나지 않음) |
| 위험 파일 차단 (`.exe .bat .ps1 .js` …), 파일명 정리, 크기 상한(기본 50MB) | ✅ | 경로 문자 제거, `..` 무력화 |
| 이동 · 태그 · 정보 수정 · 일괄 작업(이동/태그/즐겨찾기/삭제/만료일) | ✅ | 일괄은 건별 결과 반환, 숨은 문서와 없는 문서의 오류가 동일 |
| ZIP **내보내기** (+`_manifest.csv`) | ✅ | 다운로드 권한이 있는 문서만, CSV 수식 주입 방어 |
| 외부 폴더 문서 자동 수집 (증분, manifest 규칙, 삭제·권한 변경 반영) | ✅ | 같은 목록·검색·댓글·즐겨찾기에 통합 (읽기 전용) |

## 실측 성능 (이 개발 환경, 단일 프로세스, SQLite)
| 규모 | 검색 | 대시보드 | 문서 1건 등록(색인 갱신 포함) | 색인 전체 재구성 |
|---|---|---|---|---|
| 관리 문서 5,000건 | ≈100 ms | ≈75 ms | ≈130 ms | ≈120 ms (변경 없는 청크 재사용) |

권한이 적은 사용자(외부 협력사)도 같은 시간대입니다. 수만 건을 넘기면 색인(메모리)과 SQLite 단일 노드가 한계이므로 검색 엔진 분리가 필요합니다.

## 포함하지 않은 것 (솔직한 한계)
- **OCR**(스캔 PDF·도면 이미지 글자 인식), **브라우저 안 PDF/Office 뷰어**(텍스트 미리보기 + 이미지 미리보기 + 다운로드만)
- **Office 온라인 공동 편집**, 전자서명, 동적 워터마크/DRM, 바이러스 검사 연동
- **조직도 계층**(부서는 평면), 사용자·그룹 관리 화면(사용자는 `users.json`, 실제 운영은 SSO/프록시·LDAP 연동 필요)
- **접근 요청 워크플로우**(존재를 숨기는 정책과 충돌해 보류), 메이저/마이너 버전 번호(정수 버전)
- **고가용성·다중 노드·다중 테넌트** (단일 노드 설계, 백업/복구로 운영)
- 실제 Slack 워크스페이스·실제 LLM/임베딩 서버·Windows 실행은 이 환경에서 확인하지 못했습니다.
