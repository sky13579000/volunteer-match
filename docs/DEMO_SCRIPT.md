# 시연 시나리오 (약 20분)

준비: `start-server.bat` 또는 `py -m edm_ai demo --reset` → 안내된 주소 접속. 로그인 화면에서 사용자를 고릅니다.

| 사용자 | 역할 |
|---|---|
| 김유치 (MICE유치팀, L2) | 영업·대관 담당 |
| 박재정 (경영지원팀, L3, finance) | 결재자·재무 |
| 이인사 (인사팀, L3, hr) | 인사 기밀 열람 |
| 최협력(외부, L1) | 외부 협력사 |
| 서기록 (시설운영팀, records) | 기록물 관리 담당 |
| 관리자 (admin) | 운영 |

## 1. "권한이 곧 검색 범위" (4분)
1. **김유치** → AI 질의응답 → `제주관광공사 MICE 위크 계약 금액과 납기 지연 이슈는?` → 답변의 `[E1]` 인용, 계약 DB 행에서 **마진율이 가려진 것**(●●●) 확인
2. **박재정**으로 같은 질문 → 마진율·원가 문서까지 나옴
3. **김유치** → `김유치 성과 등급과 보너스` → **근거 없음**(인사 기밀은 아예 후보에서 제외)
4. **최협력** → 같은 계약 질문 → 계약·메일·DB 모두 안 나옴, 공개된 전시장 배치 검토만 보임
> 메시지: "먼저 거르고 나중에 순위를 매깁니다. AI가 모르는 문서는 말하지 못합니다."

## 2. 문서 라이프사이클 (6분)
1. 김유치 → 문서함 → **양식으로 작성**(시설 대관 계약서) → 폼 입력, 미리보기 → 저장 (계약서는 초안)
2. **결재 요청**(박재정) → 박재정 로그인 → 알림 팝오버/결재함 → **승인** → 현행 버전, AI 답변에 반영
3. 김유치 → **온라인 편집**으로 수정 → 새 버전(v2), 결재 전까지 v1이 현행 → 버전 탭에서 비교
4. **제주도청 견적서**(반려 예시)의 DB 불일치 경고: 문서 1.5억 vs DB 1.2억
5. **일정 캘린더**(2026-12): 계약 납기가 문서와 업무 DB 양쪽에서 표시

## 3. 기록물·보안 (6분)
1. 김유치 → `참가자명단_예시` 문서 → **개인정보 검출 배너**(주민번호 2건, 값은 표시·저장 안 함)
2. **서기록** → 기록물 관리 → 폐기 대상(2019 세미나) 선택 → 사유 → **폐기 심의 신청**
3. **관리자** → 같은 화면 → **승인·폐기**(신청자와 다른 사람만 가능) → **폐기 대장**에 해시와 승인자 기록
4. 관리자 → 감사 로그 → "무결성 정상(해시 체인)" · 리포트 화면(결재 소요·AI 근거 확보율·보존 예정)
5. 권한 신청: 최협력이 문서번호로 신청 → 김유치 승인 → 문서가 열림 (신청 단계에서는 문서 존재 여부가 드러나지 않음)

## 4. 연동 (4분)
1. 관리자 → 연동 관리 → **API 키 발급**(조회 전용) → 키는 한 번만 표시, 관리 API 호출은 403
2. 그룹웨어 수신/웹훅 개념은 `docs/INTEGRATION.md` 도식으로 설명(실제 연동은 고객 그룹웨어 사양 확인 후)

## 시연 팁
- 예시 데이터는 모두 가상입니다(주민번호·전화번호·금액·기관명 포함). 센터 규정은 "예시 초안"으로 표시되어 있습니다.
- 초기화: `--reset`. 다크 모드: 좌하단 버튼. 빠른 이동: `Ctrl+K`.
